تأكيد جلسة واها (WAHA)

تأكد الجلسة الجديدة مضبوطة صح قبل أي اختبار.

  1. افتح لوحة واها → Sessions → تأكد اسم الجلسة default وحالتها WORKING (خضراء).
  2. افتح إعدادات الجلسة (⚙️) → قسم Engine Settings → تأكد المحرك NOWEB مو WEBJS.
  3. بنفس الإعدادات، قسم Webhooks → تأكد الرابط بالضبط: 
    https://moh701735.app.n8n.cloud/webhook/wa-webhook
  4. بنفس الويبهوك، حقل Events → لازم يكون محدد message بس (شيل أي حدث ثاني مثل message.any أو session.status).
⚠ إذا لقيت رابط الويبهوك تغيّر لموقع غريب (مثل httpbin.org)، رجّعه فوراً للرابط الصحيح فوق — هذا صار قبل واتضح إنه يوقف كل شي.
٢

تأكيد أتمتة n8n

افتح الـ Workflow الصحيح (اسمه "AI Marketing Agent - WhatsApp (مصحح)") وتأكد من هذي النقاط.

  1. تأكد رابط الصفحة نفسه: 
    moh701735.app.n8n.cloud/workflow/1yckixfivAY9L3J5
    (هذا الوحيد المرتبط بجداول البيانات الصحيحة — أي رابط ثاني يعطي خطأ "Data table not found")
  2. نود "استقبال واتساب (Webhook)": Path = wa-webhook, Method = POST.
  3. أي نود من نودات الرد الثمانية (تبدأ بكلمة "رد:") → Credential = Header Auth account 5.
  4. نودات Data Table (7 نودات) → حقل Data table لازم يبين By ID مو "From list".
  5. الزر فوق يمين مكتوب Published (منشور)، لو مكتوب "Publish" اضغطه.

اختبار نظيف واحد

اختبار وحد مركّز، بدون تشتت، حتى نعرف بالضبط الوضع الحالي.

  1. من رقم غير رقم واها، أرسل بالضبط: 
    كود 1234 سوي تقرير عن الحملات
  2. انتظر ٥ ثواني، افتح واتساب وشوف هل وصل رد.
  3. بنفس الوقت بـ n8n → تبويب Executions → اضغط F5 → افتح آخر تنفيذ.
  4. لو "Succeeded" بالكامل ورد وصل فعلاً → خلص، انتقل للمرحلة ٥. لو صار خطأ، دور اسم النود والرسالة بقائمة "دليل الأخطاء" تحت.

دليل الأخطاء الشائعة

كل خطأ واجهناه فعلياً أثناء الإعداد، وسببه وحله. اضغط على أي سطر لتفتحه.

Data table … could not be found in this project
السبب الأشيع: تكون فاتح Workflow مختلف (نسخة استوردتها جديدة) مو الأصلي. تحقق من رابط الصفحة يطابق النقطة ٢.١ بالضبط. لو نفس الرابط وصار الخطأ بس أحياناً، فعّل "By ID" بدل "From list" بنفس النود (موجود بالنسخة الأخيرة أصلاً).
isStatusRankingEnabled is not a function
علة بمكتبة WEBJS نفسها (كسرها تحديث واتساب ويب). الحل: جلسة واها لازم تكون بمحرك NOWEB مو WEBJS — راجع المرحلة ١.
No LID for user / فشل الإرسال لرقم يظهر بصيغة lid
بعض الأرقام يخفي واتساب هويتها الحقيقية (خاصية lid) ولا تقدر ترسل لها إلا بنفس المعرّف المخفي كما وصل بالضبط، بدون إضافة أو حذف أي لاحقة. هذا مطبّق أصلاً بالكود الحالي.
رد مكرر (نفس الرسالة توصل مرتين)
راجع حقل Events بويبهوك واها (المرحلة ١.٤) — لازم يكون message بس، بدون message.any معاها بنفس الوقت.
"غير مصرح" أو ولا رد على رقمك الشخصي
رقمك الشخصي هو نفسه رقم واها، فرسالة "لنفسك" تُحسب صادرة منك ويتجاهلها النظام عمداً (منعاً لحلقة ردود). لازم تراسل من رقم ثاني، أو تستخدم الرمز السري كود 1234 بأول الرسالة.
Editing in another tab
نفس الـ Workflow مفتوح بتبويب متصفح ثاني بنفس الوقت. اضغط "Edit here" وسكر التبويبات الزايدة.

بعد ما يشتغل واتساب بالكامل

هذي الخطوات التالية بعد ما يوصلك رد ناجح، حتى تكتمل الدورة كاملة (فيسبوك + تيك توك).

  1. ربط Meta Ads: التأكد إن Credential "Facebook Graph account" مفعّل وله صلاحية على حسابك الإعلاني الحقيقي.
  2. ربط TikTok Business API: إنشاء Credential جديد وربطه بنودات TikTok (تستخدم نفس Header Auth account 2 حالياً كمكان مؤقت — تحتاج مفتاح TikTok الحقيقي).
  3. اختبار أمر حقيقي كامل: "أنشئ حملة فيسبوك اسمها كذا بميزانية كذا" ومتابعتها لين التنفيذ الفعلي.
  4. حذف نسخ الـ Workflow المكررة القديمة من n8n (Overview → Workflows) — إبقاء وحدة بس نشطة.
