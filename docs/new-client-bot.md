# تسليم بوت عميل جديد (من القالب النظيف) — أقل من ساعة

**القالب:** workflow `TEMPLATE - عميل جديد` (المعرّف `oTbFWVaKjfhYd19b`). غير منشور. لا يحتوي أي بيانات تخص المالك أو عميل آخر (يثبت ذلك `verify_clean.py` بصفر ملاحظات عليه، عدا الـplaceholders).
**قاعدة التسليم:** لا يُسلَّم أي بوت قبل نجاح الفاحص وفحص الجاهزية. أي فشل = لا تسليم + سبب واضح.

## ما يجهّزه المالك/العميل (10-25 دقيقة)
1. بوت تليگرام جديد من @BotFather، ثم التوكن.
2. معرّف تليگرام الرقمي للعميل (chat id).
3. توكن TikTok للعميل (Access-Token) وأرقام حساباته الإعلانية.
4. (اختياري) Meta: Access Token لمستخدم النظام + معرّف الحساب الإعلاني والصفحة.
5. في n8n: أنشئ credentials للعميل: Telegram (توكن البوت)، Header Auth `Access-Token - <الاسم>` (Header = `Access-Token`)، Facebook Graph (إن وُجد). أعطني أسماءها.
6. في n8n: على `TEMPLATE - عميل جديد` ← ⋯ ← Duplicate ← سمّه `<اسم العميل>`. لا تنشره.

## ما أنفذه أنا (15-25 دقيقة)
1. أنشئ 12 جدولاً للعميل (11 + جدول الجدولة) (`create_data_table`) بنفس أعمدة جداول القالب (القائمة بـ `scripts/client-bot/tables.json`).
2. أضيف صف العميل بجدول «حساب العميل» (chat id، اسم، حسابات Meta/TikTok) وصفاً بجدول «قائمة المصرح لهم» (active=true).
3. `python3 scripts/client-bot/provision.py details.json config.json ops` ثم أطبق ملفات `ops.N.json` بـ `update_workflow` (≤100 عملية لكل دفعة). لا تنسخ من بوت عميل أبداً: القالب فقط (نسخة بوت علي فشلت بفاحص النظافة بـ113 ملاحظة بينها توكن ثابت وأسماء المالك).
4. `python3 scripts/client-bot/verify_clean.py details.json ops.verify.json` ← يجب صفر ملاحظات.

## فحص الجاهزية (قبل النشر) — يجب نجاحه كله
| # | الفحص | الطريقة |
|---|---|---|
| 1 | بوت تليگرام يعمل ويصل لمحادثة العميل | `getChat` بالـcredential لمعرّف العميل |
| 2 | توكن TikTok صالح لكل حساب إعلاني | `advertiser/info` ← `code 0` و`STATUS_ENABLE` |
| 3 | حساب Meta سليم | `act_X?fields=account_status` ← 1 (مو 9/2/3) |
| 4 | الصفحة وإنستغرام مربوطين بالحساب | `promote_pages` يحتوي الصفحة المطلوبة (بالمعرّف مو بالاسم) |
| 5 | الجداول الـ12 موجودة وصف العميل موجود | قراءة الجداول |
| 6 | رابط الوسائط بلا توكن يعمل | تنزيل ملف عبر `media-<key>` داخل n8n |
| 7 | لا بيانات تخص المالك/عميل آخر | `verify_clean.py` |
| 8 | أول رسالة تجريبية من العميل تُرد عليها | بعد النشر، رسالة «مرحبا» من العميل |

إذا فشل أي فحص: لا أنشر ولا أسلّم. أرسل لك السبب والإجراء (مثلاً: «الحساب بفترة سماح دفع، ادفع من Ads Manager»).

## حدود لا يغطيها الفحص (تُصلح عند العميل)
مشاكل حسابات العميل نفسها: دفع Meta، حساب TikTok معلّق، صفحة غير مصرّح بها. الفحص يكتشفها قبل التسليم.

## ملفات
- `scripts/client-bot/template_fixes.py`: يطبّق إصلاحات القالب على أي نسخة (بوت قديم أو قالب جديد).
- `scripts/client-bot/provision.py`: يجهّز نسخة القالب لعميل.
- `scripts/client-bot/verify_clean.py`: بوابة التسليم.
- `scripts/client-bot/tables.json`: جداول القالب والأدوار.
